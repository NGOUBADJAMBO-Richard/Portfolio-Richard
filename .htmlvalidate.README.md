# Configuration html-validate

`npx html-validate index.html`

Deux règles du preset `recommended` sont désactivées. Ce sont des préférences de
style, pas des règles de validité HTML : le document reste conforme HTML5 sans
elles, et les réactiver produirait 102 erreurs sans corriger un seul défaut réel.

## `void-style` (56 occurrences)

Le projet écrit les éléments vides en syntaxe auto-fermante (`<meta ... />`,
`<link ... />`, `<img ... />`). C'est du HTML5 valide — la barre oblique est
ignorée par l'analyseur — et c'est la convention appliquée de bout en bout dans
`index.html`. Uniformiser vers `<meta ...>` toucherait 56 lignes pour zéro gain
fonctionnel.

## `no-inline-style` (46 occurrences)

Le projet s'appuie volontairement sur des styles inline pour les ajustements
ponctuels (marges de titres, couleurs de puces de timeline, tailles de boutons).
Les extraire en classes est une refonte du CSS, pas une correction de validité.

## Règles conservées actives

Tout le reste est actif, en particulier :

- `close-order` / `element-permitted-content` — structure du document
- `no-raw-characters` — encodage des entités
- `prefer-native-element` — préférer les éléments natifs aux `role=`
- `wcag/*` — règles d'accessibilité
